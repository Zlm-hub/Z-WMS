# ModernWMS 环境配置与启动指南

> 适用范围：Z-WMS 仓库（上游 ModernWMS 二开 + 前端 v2 + rebuild 部署方案）。

## 结论先行：两种启动方式

| | 方式 A：Docker 一键部署（推荐） | 方式 B：源码运行（二开调试） |
|---|---|---|
| 需要安装 | Docker Desktop（Win/Mac）或 Docker Engine + Compose v2（Linux） | .NET 7 SDK + Node.js ≥ 18 |
| 需要装数据库 | ❌ 不用（默认 SQLite） | ❌ 不用（改用 SQLite 即可） |
| 启动命令 | 3 条命令 | 后端 `dotnet run` + 前端 `npm run dev` |
| 适合 | 直接使用 / 部署到服务器 | 改代码、调试、二开 |
| 资源占用 | 约 300MB（三容器） | 开发机常规配置即可，2C/2G 云服务器也能跑容器版 |

默认账号：`admin / 1`

## 方式 A：Docker 一键部署（推荐）

### 环境要求

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10/11（Docker Desktop + WSL2）、macOS、任意 Linux |
| Docker | Docker Engine ≥ 20.10，Compose v2（`docker compose version` 能跑通即可） |
| 内存 | ≥ 2GB 空闲 |
| 端口 | 宿主机 20011（后端）、8080 / 8081（两套前端）未被占用（占用可在 `.env` 里改） |

### 启动步骤

```bash
cd Z-WMS/rebuild

cp .env.example .env       # ① 生成环境配置（按需修改，尤其生产环境改 JWT 密钥）
bash deploy.sh             # ② 构建两个后端/前端镜像并启动（或手动: docker compose up -d --build）
```

首次启动会自动：建 SQLite 库（用修复过 schema 的种子库，自带菜单/角色/admin 账号）→ 起三容器。

### 访问地址

| 服务 | 地址 | 说明 |
|---|---|---|
| 前端 v2（Vue3 重做版，推荐） | http://localhost:8081 | 全功能 + 统计分析 + 数据大屏 + 3D 库房 |
| 前端 v1（原版复刻） | http://localhost:8080 | 对照原版 UI |
| 后端 API | http://localhost:20011 | Swagger 文档在根路径 |
| Hangfire 面板 | http://localhost:20011/hangfire | Basic 认证，账号见 `.env` |

### 修改配置（.env）

`rebuild/.env.example` → 复制为 `.env` 后修改，`docker compose up -d` 重新生效：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `WMS_DB_TYPE` | `SqlLite` | 数据库类型；`MySql` 需同时启用 compose 里 mysql 服务段 |
| `WMS_MYSQL_CONN` | 见文件 | MySQL 连接串 |
| `WMS_JWT_SIGNINGKEY` | 内置长随机串 | **生产必改**，`openssl rand -hex 48` 生成 |
| `WMS_HANGFIRE_USER` / `WMS_HANGFIRE_PASS` | `admin` / `hangfire2026` | Hangfire 面板 Basic 认证 |
| `BACKEND_PORT` / `FRONTEND_V1_PORT` / `FRONTEND_V2_PORT` | `20011` / `8080` / `8081` | 宿主机端口 |
| `MYSQL_ROOT_PASSWORD` | `modernwms` | 启用 mysql 服务段时生效 |

### 数据持久化与重置

- 数据落盘在 docker volume `wms-data`（SQLite wms.db），`docker compose down` 不丢数据。
- **想彻底重置**（恢复出厂种子库）：
  ```bash
  docker compose down
  docker volume rm rebuild_wms-data
  docker compose up -d
  ```
  （volume 只在为空时才从镜像填充种子库，这是 Docker 机制，改 seed 后必须删卷重建。）

## 方式 B：源码运行（二开调试）

### 环境要求

| 项 | 要求 | 检查命令 |
|---|---|---|
| .NET SDK | **7.0**（原项目目标框架，别用 8/9） | `dotnet --list-sdks` |
| Node.js | ≥ 18（前端 v2 用 vite 4；本机 22 实测通过） | `node -v` |
| npm | 随 Node 附带 | `npm -v` |
| 数据库 | 默认改用 SQLite，**无需安装**；如用 MySQL/SqlServer/PostGres 见下文「四库切换」 | — |

### 后端启动（端口 20011）

```bash
cd Z-WMS/backend        # 仓库根下的 backend/

# ① 首次运行：把修复版种子库放到宿主项目目录（SQLite 库文件按工作目录相对路径找）
cp rebuild/seed/wms.db ModernWMS/wms.db   # 即 backend/ModernWMS/wms.db

# ② 切默认数据库为 SQLite（原版 appsettings 默认 MySql，不装 MySQL 会起不来）
#    编辑 backend/ModernWMS/appsettings.json："Database": { "db": "SqlLite" }

# ③ 跑（在 backend/ 目录下）
dotnet run --project ModernWMS
```

安全相关环境变量（可选，等价于 appsettings/代码默认值）：

| 环境变量 | 说明 |
|---|---|
| `WMS_JWT_SIGNINGKEY` | JWT 密钥（不设则用 appsettings 里的 TokenSettings.SigningKey） |
| `WMS_HANGFIRE_USER` / `WMS_HANGFIRE_PASS` | Hangfire 面板认证（都不设则仅允许本机访问） |

PowerShell 示例：`$env:WMS_JWT_SIGNINGKEY="xxx"; dotnet run --project ModernWMS`

### 前端 v2 启动（端口 5173）

```bash
cd Z-WMS/frontend-v2
npm install            # 首次
npm run dev            # 开发模式，热更新
npm run build          # 生产构建 → dist/（容器部署用）
```

- API 基址自动取「当前页面域名 + 20011」，本地 dev 无需任何配置；后端不在本机时才配 `.env`（复制 `.env.example`）里加 `VITE_API_BASE=http://<后端IP>:20011`。
- 登录后动态菜单由后端 `/rolemenu/menus` 驱动，所以**先起后端再开前端**。

### 原版前端（v1，可选）

`frontend/`（上游 v1）：`yarn install` 后 `yarn vite build`（原项目用 yarn，且需跳过 vue-tsc 类型检查，构建脚本已内置处理）。日常二开建议只跑 v2。

## 四库切换（原版能力，保留；四种库全部导入即用 + 实测闭环）

`Database:db` 支持 `SqlLite` / `MySql` / `SqlServer` / `PostGres`，对应 `ConnectionStrings` 里同名连接串。

**注意**：项目没有 EF 迁移、启动不会自动建表。SQLite 走种子库（表已建好）；其余三种库均提供「导入即用」的 DDL + 数据脚本，均由同一套工具从 EF 模型 / SQLite seed 生成：

| 数据库 | 建库脚本 | 导入命令 | 实测结果 |
|---|---|---|---|
| SQLite | `rebuild/seed/wms.db` | 直接拷为 `backend/ModernWMS/wms.db` | 全量 7 套件 108 步全过（CI） |
| MySQL | `mysql_schema.sql` + `mysql_seed.sql` | 见下 | s1/s4/s7 共 55 步全过（CI e2e-mysql job） |
| PostgreSQL | `postgres_schema.sql` + `postgres_seed.sql` | 见下 | 55 步全过（postgres:16 容器实测） |
| SQL Server | `sqlserver_schema.sql` + `sqlserver_seed.sql` | 见下 | 55 步全过（azure-sql-edge 容器实测） |

### MySQL

```bash
mysql -uroot -p -e "CREATE DATABASE wms DEFAULT CHARACTER SET utf8mb4"
mysql -uroot -p wms < rebuild/seed/mysql_schema.sql
mysql -uroot -p wms < rebuild/seed/mysql_seed.sql
# 后端环境变量：Database__db=MySql + ConnectionStrings__MySqlConn
```

### PostgreSQL

```bash
createdb wms                                   # 或 psql -c "CREATE DATABASE wms"
psql -U postgres -d wms -v ON_ERROR_STOP=1 -f rebuild/seed/postgres_schema.sql
psql -U postgres -d wms -v ON_ERROR_STOP=1 -f rebuild/seed/postgres_seed.sql
# 后端环境变量：Database__db=PostGres + ConnectionStrings__PostGresConn
```

### SQL Server

```bash
sqlcmd -S <host> -U sa -P <pwd> -Q "CREATE DATABASE wms"
sqlcmd -S <host> -U sa -P <pwd> -d wms -i rebuild/seed/sqlserver_schema.sql
sqlcmd -S <host> -U sa -P <pwd> -d wms -i rebuild/seed/sqlserver_seed.sql
# 后端环境变量：Database__db=SqlServer + ConnectionStrings__SqlServerConn
# 连接串建议带 TrustServerCertificate=True（本机自签证书）
```

### 脚本怎么来的 / 怎么重新生成

- **DDL**：`rebuild/tools/schemagen` 复用后端 EF 模型反射注册结果，`GenerateCreateScript()` 产出权威建表脚本（35 表含主键/索引/FK）。实体模型变更后重跑：
  ```bash
  dotnet run --project rebuild/tools/schemagen -- mysql      rebuild/seed/mysql_schema.sql
  dotnet run --project rebuild/tools/schemagen -- postgresql rebuild/seed/postgres_schema.sql
  dotnet run --project rebuild/tools/schemagen -- sqlserver  rebuild/seed/sqlserver_schema.sql
  ```
- **数据**：`rebuild/tools/seed2sql.py` 把 SQLite seed 转成对应方言 INSERT（seed 数据变更后同步重跑）：
  ```bash
  python rebuild/tools/seed2sql.py rebuild/seed/wms.db rebuild/seed/postgres_schema.sql postgres rebuild/seed/postgres_seed.sql
  ```
  转换器已处理方言差异：标识符引号、MySQL 反斜杠转义、`SET IDENTITY_INSERT` 开合、PostgreSQL `boolean` 列 0/1→TRUE/FALSE、插入后 `setval()` 同步 identity 序列、按外键依赖拓扑排序插入。

### 已知行为差异（非 Bug）

- C# 侧 `DateTime.MinValue`（0001-01-01）经 MySqlConnector 写入会自动钳制为 1900-01-01（SQLite/PG/SqlServer 存原值），业务语义为"空占位日期"，不影响流程
- PostgreSQL 建表用 `GENERATED BY DEFAULT AS IDENTITY`，显式插入 id 后必须 `setval` 同步序列（seed 脚本已内置）
- SQL Server 全部表带 `IDENTITY`，seed 脚本用 `SET IDENTITY_INSERT ON/OFF` 包裹（引擎会自动重设 identity 种子，无需额外处理）

## 生产上线检查清单

- [ ] `.env` 里改掉 `WMS_JWT_SIGNINGKEY`（≥64 位随机串）
- [ ] 改掉 Hangfire 默认密码（`WMS_HANGFIRE_PASS`）
- [ ] 改掉默认账号 `admin/1`（登录后在「用户管理」改密；v2 前端密码已是 PBKDF2 存储）
- [ ] 数据定期备份：备份 docker volume `wms-data` 里的 `wms.db`（连同 `-wal`/`-shm` 两个文件）
- [ ] 建议前置 nginx/反向代理加 HTTPS（前端 API 直连 `域名:20011`，TLS 需在 20011 前再挂一层）
- [ ] 端口仅放行必要项：8081/8080 面向用户，20011 可只对内网开放（前端仍能访问）

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 改了配置不生效 | compose 环境变量在容器创建时注入，需 `docker compose up -d`（会自动重建受影响容器） |
| 登录报 401 / 系统异常 | 改过 `WMS_JWT_SIGNINGKEY` 后旧 token 全部失效，重新登录即可 |
| 重建镜像后菜单/数据"回档" | volume 陷阱：删 `rebuild_wms-data` 卷再 `up -d` |
| 8080 被占用 | `.env` 改 `FRONTEND_V1_PORT` |
| MySQL 模式报表不存在 | 导入 `rebuild/seed/mysql_schema.sql` + `mysql_seed.sql`（见「四库切换」），compose 里 mysql 健康检查通过后再起 backend |
